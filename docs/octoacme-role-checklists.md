# OctoAcme Role-Specific Checklists

## Purpose
These checklists provide role-specific guidance for each project phase, ensuring that all team members understand their responsibilities and deliverables at each stage.

---

## Initiation Phase Checklists

### Product Owner Checklist - Initiation
- [ ] Define initial product vision and goals
- [ ] Identify key features and MVP scope
- [ ] Contribute to success metrics in project one-pager
- [ ] Identify primary stakeholders
- [ ] Review and approve problem statement
- [ ] Provide initial prioritization guidance

### Business Analyst Checklist - Initiation
- [ ] Conduct stakeholder interviews
- [ ] Document initial requirements and pain points
- [ ] Contribute to problem statement
- [ ] Identify data and integration needs
- [ ] Create initial stakeholder map
- [ ] Document current state workflows (if applicable)

### QA Lead Checklist - Initiation
- [ ] Review project one-pager for quality implications
- [ ] Identify quality risks (performance, security, scalability)
- [ ] Assess testing resource needs
- [ ] Identify critical quality requirements
- [ ] Document initial quality standards
- [ ] Estimate testing effort at high level

### Change Manager Checklist - Initiation
- [ ] Conduct change impact assessment
- [ ] Identify stakeholders affected by change
- [ ] Document organizational readiness factors
- [ ] Assess change complexity and risk
- [ ] Create initial stakeholder engagement plan
- [ ] Identify communication and training needs

### User Advocate Checklist - Initiation
- [ ] Conduct initial user research
- [ ] Document user pain points and needs
- [ ] Contribute user insights to problem statement
- [ ] Identify user personas (if needed)
- [ ] Define usability and accessibility requirements
- [ ] Document user success criteria

## Planning Phase Checklists

### Product Owner Checklist - Planning
- [ ] Prioritize backlog items for first sprint/iteration
- [ ] Define acceptance criteria with the team
- [ ] Review and refine user stories
- [ ] Clarify feature scope and boundaries
- [ ] Participate in kickoff meeting
- [ ] Approve Definition of Done
- [ ] Make go/no-go decision for execution

### Business Analyst Checklist - Planning
- [ ] Document detailed requirements for priority items
- [ ] Create process flows and use cases
- [ ] Define acceptance criteria with Product Owner
- [ ] Review backlog for completeness and clarity
- [ ] Identify data requirements and integrations
- [ ] Document business rules and logic
- [ ] Participate in estimation sessions

### QA Lead Checklist - Planning
- [ ] Review acceptance criteria for testability
- [ ] Define testing strategy (unit, integration, e2e)
- [ ] Estimate testing effort for backlog items
- [ ] Identify test environments and data needs
- [ ] Contribute to Definition of Done (quality gates)
- [ ] Document test plan approach
- [ ] Identify automation opportunities

### Change Manager Checklist - Planning
- [ ] Create detailed communication plan with timeline
- [ ] Develop training plan and materials outline
- [ ] Schedule stakeholder engagement touchpoints
- [ ] Identify champions and change agents
- [ ] Plan rollout approach and timeline
- [ ] Define success metrics for adoption
- [ ] Create feedback collection mechanism

### User Advocate Checklist - Planning
- [ ] Review user stories for user-centricity
- [ ] Ensure acceptance criteria reflect user needs
- [ ] Create or refine user personas
- [ ] Document user workflows and journeys
- [ ] Identify usability and accessibility requirements
- [ ] Plan user testing sessions
- [ ] Provide input on Definition of Done

## Execution Phase Checklists

### Product Owner Checklist - Execution
- [ ] Attend daily standups (or be available async)
- [ ] Clarify requirements and answer questions promptly
- [ ] Review work-in-progress during demos
- [ ] Make scope decisions when blockers arise
- [ ] Provide feedback on completed work
- [ ] Adjust priorities based on learnings
- [ ] Approve completed work against acceptance criteria

### Business Analyst Checklist - Execution
- [ ] Answer questions about business logic and workflows
- [ ] Clarify requirements as needed
- [ ] Review prototypes and provide feedback
- [ ] Support developers with edge case scenarios
- [ ] Document changes to requirements (if any)
- [ ] Participate in backlog refinement
- [ ] Coordinate with QA on test scenarios

### QA Lead Checklist - Execution
- [ ] Execute test plans (manual and automated)
- [ ] Track and report defects
- [ ] Coordinate daily with developers on test status
- [ ] Review code for testability (if applicable)
- [ ] Update test documentation
- [ ] Report quality metrics and risks
- [ ] Participate in bug triage and prioritization

### Change Manager Checklist - Execution
- [ ] Send regular updates to stakeholders
- [ ] Conduct training sessions as scheduled
- [ ] Gather feedback on readiness and concerns
- [ ] Address resistance and support needs
- [ ] Coordinate with project team on communication
- [ ] Monitor adoption indicators (if pilot/early access)
- [ ] Update training materials based on product changes

### User Advocate Checklist - Execution
- [ ] Review prototypes and provide usability feedback
- [ ] Conduct user testing sessions (if planned)
- [ ] Participate in sprint reviews/demos
- [ ] Raise usability concerns and suggestions
- [ ] Document user feedback and insights
- [ ] Collaborate with developers on UX improvements
- [ ] Ensure accessibility standards are met

## Deployment Phase Checklists

### Product Owner Checklist - Deployment
- [ ] Review completed features against acceptance criteria
- [ ] Approve release candidate
- [ ] Participate in go/no-go decision
- [ ] Review release notes
- [ ] Prepare for post-release feedback collection
- [ ] Define success criteria for release monitoring
- [ ] Plan next iteration priorities

### Business Analyst Checklist - Deployment
- [ ] Support UAT validation
- [ ] Document any gaps identified during UAT
- [ ] Validate business workflows in production-like environment
- [ ] Review release notes for accuracy
- [ ] Prepare for post-release support questions
- [ ] Document lessons learned on requirements process
- [ ] Identify follow-up requirements for next iteration

### QA Lead Checklist - Deployment
- [ ] Execute smoke tests in staging
- [ ] Validate all critical defects are resolved
- [ ] Review deployment checklist
- [ ] Sign off on release readiness
- [ ] Participate in go/no-go decision
- [ ] Prepare post-deployment verification plan
- [ ] Monitor for production issues after release
- [ ] Document quality metrics for retrospective

### Change Manager Checklist - Deployment
- [ ] Coordinate rollout communication (announcements)
- [ ] Ensure support resources are available
- [ ] Monitor adoption metrics
- [ ] Address immediate user concerns
- [ ] Collect post-deployment feedback
- [ ] Celebrate launch with stakeholders
- [ ] Plan follow-up support and check-ins
- [ ] Document lessons learned on change process

### User Advocate Checklist - Deployment
- [ ] Facilitate UAT with end-users
- [ ] Document user feedback from UAT
- [ ] Ensure critical usability issues are addressed
- [ ] Validate accessibility in production-like environment
- [ ] Participate in go/no-go decision
- [ ] Prepare for post-launch user feedback collection
- [ ] Plan follow-up user research (if needed)
- [ ] Monitor user satisfaction metrics

## Using These Checklists

### Tips for Teams
1. **Customize**: Adapt these checklists to your project's specific needs
2. **Reference Early**: Review checklists at the start of each phase to align on expectations
3. **Track Progress**: Use project boards or tools to track checklist completion
4. **Identify Gaps**: If a checklist item is consistently skipped, discuss whether it's necessary
5. **Update Over Time**: Improve checklists based on retrospective feedback

### For Project Managers
- Share relevant checklists with team members at phase transitions
- Use checklists in status updates to show progress
- Identify blockers when checklist items can't be completed

### For Individual Contributors
- Review your role's checklist at the start of each phase
- Raise concerns if you can't complete a checklist item
- Use checklists to communicate your progress to the team
- Suggest improvements based on your experience
